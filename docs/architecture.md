# Architecture

Architecture defines how components work together to produce and maintain the content production product’s required outcomes. Each section establishes a distinct architectural responsibility. Read the sections governing the affected components and operations, and follow references to their dependencies.

Product owns system purpose and scope; User Design owns product-user behavior, language and voice; Data Model owns record meanings, identity and validity; Engineering owns implementation discipline and verification; Release owns deployment and recovery; AGENTS owns agent responsibilities, authorization and governing-document changes. Architecture references those requirements and defines how components fulfill them.

## Client Research and Evidence Use

Research the client’s own website before writing to understand the practice’s providers, credentials, treatments, technology, philosophy, locations, differentiators, and terminology relevant to the article.

After researching the client’s own website, use authoritative third-party sources to support the article. Treat the URLs accompanying the assignment as research starting points rather than source material to rewrite, as required by [Assignment](assignment.md#long-form-seoaeo-content-standards).

[User Design](userdesign.md#article-content-and-writing-standards) owns the resulting article’s customization, evidence, and writing requirements. [Data Model](data-model.md#client-information) owns the distinctions and provider associations the research must preserve.
