# Article Drafts and Feedback

Article folders use the practice and fixed assignment prompt number. Each reviewed draft has its own version folder, starting with `v001`. A version folder contains the article, its images, preview, brief, research support, prepared comments, assessment, and provenance so the reviewed text and context stay together.

Preserve a version once feedback refers to it. Put the next revised or replacement draft in `v002`, then `v003`, rather than overwriting the reviewed version. Retain these versions for feedback comparison from this point forward. Earlier drafts deleted at Vikas's request are not restored.

Record feedback in [Vikas Article Feedback](vikas-article-feedback.md), with the practice, assignment prompt number, version, and passage or image. Clean up the feedback wording without changing its meaning. Recording feedback does not authorize revisions or governing-document changes.

## Production Provenance

Each version's `provenance.md` identifies its production run and the article hash. A shared run record links to the full repository commit used at production. Prefer committed production inputs for future runs. If relevant inputs are uncommitted, preserve their diff with the run and record that the commit alone is insufficient. Record provenance when the run starts and the final article hash when the version is preserved.

The current v001 drafts have [retrospectively reconstructed provenance](runs/2026-10-07-three-practice-trial/README.md), including the identified governing-document patch and its limits. No clean production commit or fully reproducible run is claimed.
